# Управление вводными через Google Таблицу

Вводные калькулятора на сайте берутся из листа «Вводные» Google Таблицы. Таблица закрытая: доступ к ней выдаёт владелец в самой таблице. Сайт получает только этот лист и только через сервер сайта.

## Как это устроено

1. Человек меняет число в колонке «Значение» листа «Вводные».
2. Посетитель открывает страницу сайта. Страница спрашивает вводные у сервера: `GET /api/inputs`.
3. Сервер отдаёт свою копию. Если копии больше 30 секунд, он сначала перечитывает таблицу.
4. Страница пересчитывает показатели в браузере.

Сервер проверяет каждое значение: число на месте числа, в допустимых пределах. Ячейка, не прошедшая проверку, не применяется: сайт продолжает считать на прежнем значении, а страница `/control/inputs` показывает, что именно не принято. Если таблица недоступна, сайт работает на последней исправной копии; она переживает перезапуск сервера.

## Где смотреть

| Что | Адрес |
|---|---|
| Текущие вводные, время чтения, непринятые ячейки, кнопка «Обновить сейчас» | `https://colob.spi.ski/control/inputs` |
| То же в виде данных | `https://colob.spi.ski/api/inputs` |
| Калькулятор, который считает на этих вводных | `https://colob.spi.ski/investor-terminal` |

## Лист «Вводные»

| Колонка | Кто заполняет | Назначение |
|---|---|---|
| Ключ | команда подключения | по нему сайт находит строку; не менять |
| Название | команда подключения | подпись для человека |
| Значение | человек | единственная колонка, которую правят |
| Единица | команда подключения | ₽, м², чеков, % |
| Пояснение | команда подключения | на что влияет |

Порядок строк и оформление можно менять. Строку можно удалить — сайт вернётся к значению по умолчанию и покажет это на `/control/inputs`. Список параметров и допустимые пределы лежат в `server/inputs-schema.json`.

## Первое подключение

1. В таблице: «Расширения» → «Apps Script». Заменить код содержимым `server/google-bridge.gs`, сохранить.
2. «Начать развёртывание» → «Новое развёртывание» → тип «Веб-приложение». Запуск: «От моего имени». Доступ: «Все». Подтвердить разрешения, скопировать адрес веб-приложения.
3. На компьютере разработчика:

```bash
npm run backend:deploy
```

```bash
npm run sheet:connect -- "<адрес веб-приложения>" "<ссылка на таблицу>"
```

Первая команда обновляет серверную часть сайта без пересборки страниц. Вторая связывает мост с сайтом, создаёт лист «Вводные» и дописывает в него недостающие строки. Значения, уже введённые в таблице, она не меняет, поэтому её можно запускать повторно — например, когда в `server/inputs-schema.json` появился новый параметр.

Доступ «Все» относится к адресу моста, а не к таблице. Мост отвечает только на запросы с ключом, который сервер сайта сообщил ему при подключении. Ключ хранится на сервере в `/srv/kolob-data/google-bridge.json` и в свойствах скрипта. Сбросить связь: меню «Колобочная» → «Сбросить связь с сайтом» в таблице, затем снова `npm run sheet:connect`.

После правки кода моста нужно выпустить новую версию: «Управление развёртываниями» → карандаш → версия «Новая» → «Развернуть». Адрес при этом не меняется.

## Вход в закрытую зону по ссылке

```bash
npm run admin:link
```

Команда печатает длинную ссылку и кладёт её в буфер обмена. Повторный запуск выдаёт новую ссылку, прежняя перестаёт работать. Выключить вход по ссылке: `npm run admin:link -- -off`. Вход по паролю работает независимо.

## Проверки

```bash
npm run test:sheet
```

Тест поднимает серверную часть и подставную таблицу и проверяет: значения по умолчанию без таблицы, чтение таблицы, окно свежести, принудительное обновление, отказ от неверных ячеек, работу на копии при недоступной таблице и после перезапуска.
