# Rules Project: Колобочная

Этот файл фиксирует текущее устройство инвесторского сайта «Колобочная» и правила дальнейшей разработки. Его задача — помочь продолжать проект на другом устройстве или передать работу внешнему разработчику без потери архитектурных решений.

## 1. Базовая информация

- Рабочий каталог проекта: `D:\Protagonist_DEV\Колобочная`.
- Единственное корректное название проекта: `Колобочная`.
- Основной тип проекта: многостраничный инвесторский сайт на React + Vite + TypeScript.
- Не создавать проект заново. Продолжать текущую архитектуру.
- Не менять логотип без отдельного согласования.
- Не менять утверждённую палитру без отдельного согласования.
- Не выбирать медиа самостоятельно из всего каталога `Madia`; использовать только вручную указанные файлы или уже заведённые поля в `src/content/media-map.ts`.

## 2. Технологический стек

- React 19.
- Vite.
- TypeScript.
- CSS: общий файл `src/styles.css`.
- Пререндер: `scripts/prerender-dist.cjs`.
- Проверки через Playwright.
- Оптимизация и подготовка медиа: Sharp и проектные scripts.

## 6. Контентные правила

- Утверждённые тексты хранить в `src/content/*.ts`, не зашивать в JSX без причины.
- Не публиковать неподтверждённые финансовые показатели.
- Не использовать публично:
  - `один цех — десять точек`;
  - количество точек первого этапа;
  - 100 чеков;
  - средний чек;
  - CAPEX;
  - EBITDA;
  - окупаемость;
  - долю инвестора.
- Не использовать формулировки «мы хотим», «мы планируем», «предполагается», «может использоваться» на публичных страницах.
- Не показывать заглушки вида «будет добавлено», «уточняется», «форма демонстрационная».
- Отсутствующие nullable-поля скрывать в компонентах.

## 7. Визуальная система

Основной визуальный язык:

- фирменный жёлтый;
- чёрный / угольный;
- тёплый светлый фон;
- крупные продуктовые фотографии;
- круг как мотив;
- новая русская эстетика без буквального фольклора;
- технологичная гастрономия.

Не использовать:

- хохлому;
- матрёшек;
- старославянскую стилизацию;
- крафтовую мешковину как основу;
- дешёвый fast food visual;
- сгенерированных маскотов как глобальный образ;
- улыбающегося сказочного колобка.

## 8. Типографика

Базовые размеры заданы в `src/styles.css`:

- `h1`: крупный hero / page hero.
- `h2`: стандартный заголовок секции.
- `h3`: заголовок карточки или элемента.
- `.section-intro p`: основной вторичный текст секции.

Правило:

- Не вводить локальные гигантские размеры заголовков без отдельного согласования.
- Если блок должен выглядеть как часть общей системы, использовать стандартный `h2`, а не отдельный `clamp(...)`.
- Исключения допустимы только для hero и уже утверждённых специальных блоков.

## 9. Адаптив и viewport-проверки

Обязательные размеры проверки:

- `1440 px` — desktop.
- `1024 px` — desktop/tablet boundary.
- `768 px` — tablet.
- `390 px` — mobile.

Базовые требования:

- нет горизонтального overflow;
- header и mobile menu не перекрывают контент;
- кнопки пригодны для touch;
- карусели используют scroll-snap;
- схемы и маршруты перестраиваются вертикально;
- текст не выходит за контейнеры;
- правые/левые колонки на узких экранах переходят в вертикальный порядок.

Скриншоты проверок сохранять в `analysis/screenshots/`.

## 12. LoopMedia и мобильный autoplay

Текущая рабочая схема мобильного autoplay зафиксирована как рабочая на реальном мобильном устройстве.

Не упрощать без отдельной причины.

Ключевые условия:

- `muted`;
- `defaultMuted`;
- `playsinline`;
- `webkit-playsinline`;
- `autoplay`;
- `loop`;
- `preload="auto"`;
- запуск через `IntersectionObserver`;
- сниженный threshold;
- `rootMargin`;
- повторные попытки при `scroll`, `resize`, `touchend`, `pageshow`, `visibilitychange`;
- fallback-кнопка play при блокировке браузером.

Если autoplay снова ломается:

1. Проверить `prefers-reduced-motion`.
2. Проверить Low Power Mode на iOS.
3. Проверить, что видео реально без аудиодорожки.
4. Проверить Range-запросы к MP4.
5. Проверить, что компонент не удалён/не заменён из DOM.

## 13. Медиа

Исходники лежат в `Madia/`. Их не изменять.

Для сайта использовать оптимизированные копии в `public/media/`.

Правила:

- не подключать тяжёлые исходные `.MOV`, `.HEIC`, большие `.JPG` напрямую;
- web-версии хранить в `public/media/...`;
- для responsive image использовать структуру `base + widths` через `ImageSpec`;
- для видео хранить MP4/WebM/poster;
- для optional media использовать `null`, а компонент должен скрывать элемент или использовать безопасный fallback;
- не показывать пользователю технические заглушки.

## 14. SEO и prerender

Сайт использует React SPA + production prerender.

Важно:

- `index.html` в dev теперь стандартный: пустой `<div id="root"></div>`;
- HTML fallback для GPT-просмотра больше не используется в dev;
- production HTML для маршрутов генерируется через `npm run build`;
- `scripts/prerender-dist.cjs` создаёт HTML и review-страницу в `dist/__review/`;
- `PUBLIC_ORIGIN` по умолчанию в prerender: `https://colob.spi.ski`.

## 15. Header и навигация

Header:

- sticky;
- glass tile effect;
- desktop dropdown;
- mobile menu;
- active state;
- dropdown закрывается при выборе пункта;
- Esc/click outside поддерживаются.

Не менять header-логику без отдельной проверки desktop/mobile.

## 16. Проверка перед завершением задачи

Минимальный набор:

- `npm run build`;
- `npm run audit:content`;
- проверить главную на 1440 и 390;
- проверить целевой блок на desktop/mobile;
- проверить отсутствие горизонтального overflow;
- проверить консоль браузера;
- если менялся media/video — проверить реальное воспроизведение, а не только наличие DOM.

Для точечных задач можно сначала запускать `npm run build:spa`, но финальная проверка перед отчётом должна быть полной: `npm run build`.
