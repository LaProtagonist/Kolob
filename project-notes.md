## 2026-07-01. Autoplay hero-video на странице `/history`

На страницу `/history` добавлено hero-видео:

- `public/media/history-origin-loop.webm` — около 1.48 МБ;
- `public/media/history-origin-loop.mp4` — около 1.66 МБ;
- видео обрезано в квадрат 720×720;
- аудиодорожка удалена;
- используется круглая маска hero-блока;
- видео работает как muted autoplay loop.

Наблюдение:

- В одном тесте видео сначала держалось на постере и стартовало заметно позже.
- При повторной проверке в других браузерах autoplay стартовал нормально.
- Поэтому код загрузки сейчас не менялся, поведение считаем штатным, но наблюдение фиксируем.

Если задержка повторится на нескольких устройствах или браузерах, возможные улучшения:

1. Для hero-видео истории заменить `preload="metadata"` на `preload="auto"`.
2. Для этого hero использовать MP4 как первый источник или временно оставить MP4-only, потому что разница с WebM небольшая, а MP4 стабильнее на мобильных браузерах.
3. Добавить повторный `play()` на событие `canplay`, если браузер задерживает старт после первого autoplay-запроса.
4. При необходимости добавить preload-ссылку в `index.html` только для критичного hero-видео:
   `<link rel="preload" as="video" href="/media/history-origin-loop.mp4" type="video/mp4">`.
5. Если и после этого старт будет медленным, сделать более лёгкую версию 640×640 или немного поднять CRF при кодировании.

Не применять эти оптимизации заранее без повторной проблемы: текущее видео достаточно лёгкое, а агрессивный preload может ухудшить загрузку остальной страницы на слабой сети.
